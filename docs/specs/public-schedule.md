# Bounded public schedules and project digests

Ticket: [13](https://github.com/as992949791/Hark/issues/13). Baseline: `v0.1.15-public-acceptance`.

Use the existing Netlify Free/Neon Free deployment, background runner, leases, handlers, queue successors and alert cadence. Preserve Clerk, original records, wallet deferral and attribution. No infrastructure purchase or UI redesign.

- A Netlify scheduled function checks every 15 minutes and dispatches at most two exact due jobs to the existing background endpoint. It does not execute scan handlers or start a persistent scheduler.
- Default off. Require the existing private worker secret/test owner plus an explicit allowlist of at most three project UUIDs. Both dispatcher and background admission check scheduled configuration; the worker additionally verifies ownership. Exclude instance-wide work, retention and invites. Original projects/research successors stay outside the demonstration allowlist.
- Selection reuses original attended/family/live-lease eligibility. Atomic scoped claims and project advisory locks serialize duplicate/sibling execution. An expired lease may be recovered; this does not prove a real 15-minute platform timeout has been exercised.
- Skip paid jobs when house data/model keys are absent, global caps are zero/exhausted, or X's own flag/caps are unavailable. Recheck at background admission. Existing adapters retain their per-call budget checks. Recorded-spend checks do not reserve in-flight charges; the remaining cumulative $1 authorization governs bounded live trials.
- Seed a project-scoped digest only on allowed owned projects with channels, without duplicating an unfinished digest during overlapping ticks. Digest jobs use the original selection, empty-window behavior and cadence; filter channels by project and owner. Success advances lastSentAt; failure keeps its window and books the original hourly retry. Preserve the original instance-wide/local digest behavior outside this path.
- Local development/verification and tests force both scheduler switches off. Use the dedicated test database and mocked dispatch/send transports to verify disabled/zero-funded mode, foreign owners/projects, due/future jobs, concurrency, expired leases, cadence and delivery failure.
- Bundle both custom functions; run supported full verification and independent Standards/Spec review against the baseline before archive/deployment. First publish disabled with paid keys omitted/caps zero. A temporary live acceptance must record actual job completion, delivery if eligible, cost reconciliation and return to disabled/zero-paid configuration. A 202 or next-check label is not completion proof. No unattended recurring paid scans/messages after the trial.

Long-run platform timeout recovery, retention automation and unconfigured Slack/Discord receipt remain later work. A scheduled function's empty disabled tick still uses platform compute; the default-off application switch prevents queue/database/provider work, not the platform invocation itself. See [Netlify scheduled functions](https://docs.netlify.com/build/functions/scheduled-functions/) and [existing platform research](../research/netlify-background.md).
