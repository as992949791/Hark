Each run made two generation calls: the complete product reading and competitor identification. No lead-scoring model was changed.

The page explicitly offers a free online trial, free design/image features, and desktop/mobile downloads. Qwen's exclusion claims conflict with those offers or lack evidence for excluding those buyers. They passed the existing literal-source grounding check: finding a source phrase does not prove that the phrase entails a restriction. DeepSeek avoided these restrictions and kept its audience description close to the site's stated scope.

DeepSeek still made mistakes: it left the pain field empty and treated the event label “Capcut World Singapore” as a service destination. Its internal brief also inferred that professional film editors and users needing advanced colour grading are non-buyers. The upstream brief intentionally permits inferred distinctions, but these remain hypotheses rather than verified product limits. Selecting DeepSeek does not fix the underlying grounding check; neither output should be treated as a fully verified product analysis.

For this input, DeepSeek is the preferred product-analysis model. The two-call reading cost roughly 4.7 times as much, with an absolute increase of $0.008417. Its elapsed time was about 3.8 seconds longer. This is one qualitative product example, not a benchmark proving general superiority; additional products and labeled expected profiles are needed to assess consistency. Token counts include provider-reported generation/reasoning usage rather than only the final JSON's length.

The advertised catalog price is not the measured bill: routes can have different prices. Refer to the [OpenRouter model page](https://openrouter.ai/deepseek/deepseek-v4.1-flash) for current providers and use returned usage costs for accounting.

## Application follow-up

A later `buildProfile` run with a new scrape returned an almost empty reading, including empty capabilities and brief, and the upstream schema accepted and persisted it. That run's page input was not saved, so the cause cannot be attributed to the scraper or the model from this evidence. It was not counted as a successful quality check. The useful DeepSeek reading from the controlled comparison was restored to the local project with an operator transaction matching the original profile/competitor writes and incrementing both profile versions. This restored snapshot, rather than that empty rebuild, is the current demonstration profile.

Version `v0.1.6-profile-validation` adds local validation and one content retry to fast/full readings. Regression tests verify that empty readings cannot overwrite a valid stored profile or its competitors. This addresses the empty-write defect; it does not establish repeatable live generation, factual accuracy, or rejection of readable challenge/login pages. No further paid evaluation was run for that change.
