# Browser creation and project switching — 2026-10-08

Scope: create a second real product through the existing signed-in UI, run its original setup/sweep under the authorized cumulative $1 budget, and verify product separation. Tracked in [issue 7](https://github.com/as992949791/Hark/issues/7).

- The new-project form refused `not-a-domain` with the existing address error. Submitting `https://cal.com` created a separate project and redirected to its Leads page, which displayed the initial-work and empty-list states. The UI request created/queued work; it did not synchronously call a model.
- Scheduler and seed remained disabled. A private operator worker claimed only this project's `discovery_initial` and `backfill` rows and ran the original runner/handlers. This verifies browser → queue → worker → persisted results → browser, with explicit operator dispatch; it does not verify an unattended production scheduler.
- The worker ran with development `smallSweep`: at most three discovery queries, four Reddit searches, one page per search and 300 posts. Production preview intentionally ignores smallSweep, so the worker's mode was set explicitly. Daily data/model caps were $0.12/$0.30 and individual AnyAPI requests capped at $0.01; model output was bounded at 6,144 tokens. No recurring scheduler or external notification was enabled.
- Both jobs finished successfully. Setup took about 71 seconds; backfill took about 24 seconds. The profile/brief are version 1, with a nonblank solution and ten capabilities. There are 71 stored evaluations and nine leads; this is a real result, not a promise that nine leads are sales-qualified or still active.
- Browser verification showed Cal.com and its nine all-time leads, with one in the last 30 days. Switching from CapCut to Cal.com changed the heading/results; switching the Product page back to CapCut restored its own name and URL without leaking the new form's fields. The two projects retain distinct IDs and their original data.
- The application ledger recorded 20 data calls, $0.010440 in data and $0.032461 in model costs for this worker run. Provider totals are reconciled again before/after the remaining modules because billed amounts can settle later. Raw traces, screenshots, driver and local snapshots stay ignored.

No source change was needed for this stage. An initial generic reload arrived at the default unqualified Leads URL and showed CapCut; verification then used explicit project URLs and the actual switcher, and checked the selected URL/heading rather than assuming the screenshot was Cal.com. Production deployment, automated scheduler operation, larger sweeps, profile factual-quality benchmarking and cross-user isolation remain separate checks.
