# Product and Sources frontend acceptance

Local acceptance on 2026-10-16 for the next bounded slice of [issue 16](https://github.com/as992949791/Hark/issues/16), from `v0.1.24-home-integration`. Existing design system, Clerk, ownership checks and provider controls remain. This is not completion of the remaining frontend or a public deployment.

## Changes

- Product fields have an explicit profile heading, paired wide-screen problem/solution fields and narrow-screen stacking. Editable lists use readable rows, larger remove targets and two independently stacked desktop columns. Forms expose busy state, preserve error/success messages and use task-specific placeholders.
- Sources retains its searches/communities/competitors/evidence order. Entry forms stack on phones; website fields sit below competitor names on phones and use the shared 40px Input. Switch hit areas are 44x40px with theme-aware blue tracks. Related Product/X settings links retain project context. Existing add/state/delete/domain actions remain.
- Product and Sources loading layouts follow their page structure. Slow navigation, pending and permission-limited rendering are not comprehensively captured; component wiring/source and the production build cover the supplied loading/disabled states.
- Saving unchanged stored empty strings previously normalized them to null, incremented the profile version and queued fresh analysis. Null/empty-equivalent facts now leave the row untouched. Actual edits still increment and enqueue; retry dispatch of an already queued brief stays intact.
