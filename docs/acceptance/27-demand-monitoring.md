# Daily monitoring and structured pain evidence

Scope: [issue 24](https://github.com/as992949791/Hark/issues/24), [spec](../specs/demand-monitoring.md). Review baseline: `v0.1.37-public-research`.

## Implemented behavior

- Save an owned product/topic condition from a research record with an existing owned email channel and positive run/lifetime USD limits. Save paused; enable/pause/delete controls and history are owner scoped. Daily admission is 24 hours after the preceding admission; the existing 15-minute scheduled tick may be late. A separate default-off monitoring switch, exact worker owner, existing live/worker controls, paid credentials, configured email sender and daily caps are required. Manual projectless research cannot join the scheduled path merely by having no project.
- One shared transaction admits an ordinary research run/job and reserves its whole ceiling against the monitor lifetime limit. Explicit retries must re-reserve the released ceiling, reject another active same-monitor run and preserve pending delivery. Saved URL conditions remain authoritative if the former product project changes its URL. It never clones the preceding run's documents. Active runs prevent another admission; terminal settled runs release unused ceiling. Failed/blocked or unresolved runs pause new creation. Deleting a monitor cancels queued work and removes conditions/hash history/pending reminders while retaining research and bill records. In-flight requests can finish under their original ceiling.
- The first completed/partial settled scan establishes a baseline without emailing old results. Later cases are compared against canonical-source and normalized original-quotation hashes; observed overlap is conservatively suppressed. This can suppress a different need in the same page, and does not establish publication recency, semantic uniqueness or independent people. Only hashes survive research-content retention.
- New cases produce a durable per-run notification record. The same background job carries delivery and retry; a failed send is stored as a safe generic error, never raw SMTP credential/error text. Pending/sending leases recover without creating paid research. Expired content is not sent, and settled expired history alone does not end a healthy monitor. Paused or removed channels stop sends. A successful normal repeat sends once, but SMTP acceptance followed by process failure can duplicate an email.
- Contextual review now returns up to four current-workaround/limitation entries per case in the existing final AI request. Each Chinese explanation has an exact quote and server-derived offsets in retained case-member documents. Foreign/fabricated quotes fail. Same-need merging retains analysis evidence. New requests require the analysis array, while cached legacy artifacts remain readable with an explicit missing-extraction state. Neither missing evidence nor a desired feature is treated as a current workaround.
- Demand and theme views show both categories and quote/source disclosures. Theme details retain case-level evidence; they do not invent an aggregate causal claim. No additional model stage was introduced.
