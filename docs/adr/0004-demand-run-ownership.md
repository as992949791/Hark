# ADR-0004: Own demand research independently from product projects

Accepted 2026-10-17. The storage/accounting foundation is implemented in v0.1.29; source collection and the research UI remain planned. A demand run belongs directly to its signed-in owner and optionally references an owned product project. A new product URL prepares only a run-owned profile within the same bounded budget; it does not invoke ordinary project creation and its automatic discovery/backfill. Topic mode requires no fake product and makes no product-fit claim. This keeps the existing product profile/scanning model intact while serving people researching a need before they have a product.

New evidence and run/job associations remain separate from existing Reddit-only SERP storage and product retrieval plans. Topic costs must enter the existing daily accounting through an explicit run reference: permit a project-less data-ledger row only with that reference, and retain a minimal billing record after evidence expiry. Reusing null-project enqueue coalescing or treating a topic as a normal product would incorrectly mix ownership, work and spend. The foundation release must verify the migration constraints, exact-job owner admission and existing project behavior before adding provider calls.

Run-owned charge rows use their demand-run/attempt association instead of the cascading product-project reference. This preserves costs when evidence expires or the optional product project is deleted; existing project-only usage readers retain their previous scope, and new research reports costs per run. Existing account deletion retains its cascading data policy.
